## Release Notes Layout

<Tabs>
  <Tab title="Monthly" icon="calendar">
    Use a monthly cadence when you publish documentation updates often. This keeps the changelog compact and easy to review.

    ```markdown
    ## November 2026

    - Added a new FAQ section.
    - Updated setup instructions.
    - Fixed formatting in examples.
    ```
  </Tab>
  <Tab title="Per release" icon="package">
    Use a per-release cadence when your documentation follows product versions. This works well for stable release cycles.

    ```markdown
    ## v1.3.0

    - Added release notes navigation.
    - Improved content structure.
    - Fixed outdated sample text.
    ```
  </Tab>
  <Tab title="Internal draft" icon="settings">
    Use an internal draft format when you want to prepare changes before publishing them. This helps your team review updates before they go live.

    ```markdown
    ## Draft notes

    - New section planned for onboarding.
    - Terminology review in progress.
    - Example links still need validation.
    ```
  </Tab>
</Tabs>

## Version History Notes

For a starter kit like Hamid Raza, your version history should stay simple at first. As the documentation matures, you can add more detail, link related pages, and split major changes into separate release sections.

A good changelog entry explains the change, the reason behind it, and the part of the documentation it affects. That approach keeps the page useful for both readers and editors.
